The phone never forwards a packet. It opens its own connections, so the traffic leaving it is ordinary app traffic.

Not tethering

A normal hotspot hands your PC to the carrier's tethering stack, which is what gets metered separately or blocked outright. Cell2Pc does something different: your PC's packets stop at the phone, and the app opens fresh connections of its own on the cellular interface.

The result is that nothing on the network sees a second device, because at the IP layer there isn't one. This is architecture, not a trick — there is no TTL rewriting or fingerprint spoofing anywhere in it.

Worth being clear: this makes the traffic identical to app traffic at the IP layer. It is not a claim of undetectability by other means, and whether you may use it is between you and your carrier's terms.

What you get

◈

Every application

A real virtual network adapter, so browsers, Steam, Windows Update and games all work. No proxy settings, nothing per-app.

⇉

Four parallel links

Traffic is spread across several connections, so one lost Wi-Fi frame stalls a quarter of it rather than freezing everything.

⟳

Reconnects itself

If the link drops, the adapter stays up and the tunnel rebuilds underneath it, so applications keep their connections.

⊘

Data caps

Usage tracked per day and per billing cycle, anchored on your carrier's cycle day. Set a cap and it stops before you overspend.

⚿

Encrypted

A pairing code authorises each PC, and every frame is sealed with AES-GCM keyed from it. Joining the Wi-Fi is not enough.

Several PCs

Up to four machines share one phone, each with its own streams and its own DNS cache.

How it actually works

Windows sees a virtual network adapter and routes everything through it. The client reads those raw IP packets, works out which are TCP and which are UDP, and multiplexes them over the Wi-Fi Direct link.

On the phone, the app parses each stream and opens a real Android socket to the destination, bound explicitly to the cellular network. It copies bytes between the two. That is the whole idea — and it is why no root and no tethering stack are involved.

Getting started

1. On the phone

Open Cell2Pc and tap Wi-Fi Direct. It shows a pairing code and a Wi-Fi passphrase — you need both, once.

2. On the PC

Run Cell2Pc, enter the pairing code, press Connect. It joins the phone's network itself and asks for elevation only at that point, because creating a network adapter is privileged.

The passphrase is only needed the first time. After that the PC remembers both, and can connect on its own whenever the phone starts sharing.

Command line

Everything the app does is available from a terminal, and --json makes any command scriptable.

cell2pc                       # prompts for the pairing code
cell2pc -t k7m2xq4p           # with a known code
cell2pc connect --for 2h      # disconnect automatically after two hours
cell2pc status                # is a tunnel running?
cell2pc doctor                # work out why it will not connect
cell2pc recover               # restore routing after a crash

doctor

Works through platform, privileges, driver, Wi-Fi group, reachability and leftover routes in order, then tells you what to do about anything it finds — rather than reporting that the connection failed.

Troubleshooting

The PC has no internet after a crash

Routing changes are journalled to disk before they are applied and replayed on next start, so this should recover on its own. If it does not:

cell2pc recover

Or run Fix my internet from the Start menu. Disabling and re-enabling the Wi-Fi adapter also clears everything.

Some sites load, others do not

Usually MTU. The tunnel probes for it, but a network in the middle can still black-hole large packets. cell2pc doctor will say more.

It says "degraded"

Fewer than four links are up. The tunnel still works with one; throughput and stall resistance drop. Usually a weak radio link.

Windows warns about the installer

The installer is not code-signed, so SmartScreen does not recognise it. That is a statement about the certificate, not the software. Choose More info then Run anyway.

How it works

Three pieces, and the middle one is where the idea lives.

The virtual adapter

Wintun on Windows, /dev/net/tun on Linux. A real network interface means every application works with no configuration — that is the main advantage over proxy-based tools, which only cover apps you configure.

The tunnel

Raw IP packets are classified and multiplexed across four parallel TCP connections. Four rather than one because a single connection means one lost frame stalls every stream behind it — which is felt as an occasional total freeze rather than as steady slowness.

Userspace NAT

The phone never forwards a packet. It parses each stream and opens an ordinary Android socket to the destination, bound explicitly to the cellular network, then copies bytes between the two. Traffic leaves the phone as that app's own traffic, which is exactly why no root and no tethering stack are needed.

UDP gets the same treatment, with a socket per flow. Without it, DNS, QUIC and games all break — which is what proxy-based tethering tools usually get wrong.

Security

The Wi-Fi group is WPA2, but a group passphrase is shared with every device that ever paired, so it is not a session secret. Two further layers:

  • Pairing code — the phone rejects any client that does not present it, so joining the Wi-Fi does not by itself grant use of the connection.
  • AES-GCM — every frame is sealed with a key derived from that code, so traffic is unreadable to anything else on the link.

Nothing is sent anywhere else. There is no account, no telemetry and no server: the phone and the PC talk directly.

Building

Requires JDK 17, the Android SDK (platform 36), and the .NET 9 SDK.

# Phone
cd android
./gradlew assembleDebug

# Desktop
cd windows/Cell2Pc.App
dotnet publish -c Release -r win-x64 -o ../../dist

# Everything, including the installer
packaging\build-release.ps1

# Tests
packaging\test.ps1

Wintun (amd64) from wintun.net must sit beside the Windows executable. The installer bundles it.
